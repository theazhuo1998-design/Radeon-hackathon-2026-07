# Radeon A/B 诊断实测（2026-08-01）

## 结论

本轮只运行了一次新的 Radeon B 组诊断，没有继续扩展或启动第二轮。

- Public Golden 模型能力从 `12/36`（33.3%）提升到 `16/36`（44.4%）。
- Public Golden 产品完成从 `17/36`（47.2%）提升到 `23/36`（63.9%）。
- Safety 保持 `36/36`（100%）。
- 5 条产品 Agent 场景仍为 `0/5`。
- B 组仍未达到模型能力 85% 和产品完成 95% 的门槛，整轮状态为 `FAIL`。

因此，当前改动有可见的总体改善，但还不能宣称 Agent 门禁通过，也不能把改善全部归因于某一个代码改动。

## 与 discrete 排序的关系

`golden-017-ingredient-priority` 的输入是“豆腐快坏了，午饭优先用掉它，菜你来搭配”。

- A 组：产品完成 PASS，但模型把 `白菜豆腐煲` 同时写进了请求菜品，模型能力本身并未通过。
- B 组：模型连续两次把 `compose_family_meal` 动作输出成普通 JSON 文本，没有产生标准工具调用；运行时按安全规则停止，领域规划器没有执行。
- 结果：该用例由产品 PASS 变为 FAIL，不能用于验证新的“按实际可用消耗比例排序”实现。

新的纯领域比例计分测试在实例打包前的本地完整测试中通过，完整测试结果为 `187/187`；但本轮真实 Provider 路径没有走到该排序代码。因此，本轮对 discrete 排序的 Radeon 端到端结论是：**未验证，而不是验证失败或通过。**

## 与“甜品 bug”的关系

当前 5 条产品场景和 36 条 Public Golden 中没有可定位的甜品用例。按照现有审计结论，仓库也仍缺少该问题的明确复现与期望行为。因此，本轮没有产生甜品 bug 的新结论，不能把总体分数变化解释为甜品问题已修复。

## 建议

暂不进入 sealed blind 或正式门禁测试。下一步应先处理“模型把工具动作写成普通 JSON 文本”的通用协议问题，并增加一条能确认领域排序实际执行的窄范围真实 Provider 回归；之后再做一次同口径复测。不要根据这一个 A/B 样本继续大范围调参。
